# ❌ ERRO HTTP 406 - Mod_Security

## 🔍 O QUE ACONTECEU

```
HTTP 406: Not Acceptable!
An appropriate representation of the requested resource could not be found.
This error was generated by Mod_Security.
```

**Significado:** O **firewall/WAF (Web Application Firewall)** do servidor está bloqueando a requisição.

---

## ⚠️ CAUSAS COMUNS

### 1. Falta de User-Agent
O Mod_Security pode bloquear requisições sem `User-Agent` ou com User-Agent suspeito.

**Solução Aplicada:** ✅
```python
headers = {
    "User-Agent": "NovoMundo-DisparadorEmail/1.0",  # Adicionado
    "Accept": "application/json",                    # Adicionado
    "Content-Type": "application/json; charset=utf-8",
    "X-API-Key": "..."
}
```

### 2. Headers Suspeitos
Alguns headers podem ser interpretados como ataque.

**Solução:** Usar apenas headers necessários e padrão.

### 3. Payload com Padrões Maliciosos
O WAF pode interpretar certos textos no JSON como SQL injection, XSS, etc.

**Verificar:** O payload que estamos enviando é limpo, mas o WAF pode ser muito restritivo.

---

## ✅ O QUE JÁ FOI FEITO

1. ✅ Adicionado `User-Agent: NovoMundo-DisparadorEmail/1.0`
2. ✅ Adicionado `Accept: application/json`
3. ✅ Mantido `Content-Type: application/json; charset=utf-8`
4. ✅ HTTP configurado (sem SSL)

Para verificar se é problema do código ou da API:

```bash

  -H "Content-Type: application/json; charset=utf-8" \
  -H "Accept: application/json" \
  -H "User-Agent: NovoMundo-DisparadorEmail/1.0" \
  -H "X-API-Key: DV_API_2025_CTRL_NOTAS_f8e9d2c1b4a6" \
  -d '{
    "nome": "Teste",
    "email": "teste@teste.com",
    "periodo": "10/2025",
    "valor_total": 100.00,
    "quantidade_os": 1,
    "data_envio": "2025-10-13T14:30:00",
    "lote_id": 999
  }'
```

Se cURL também der 406, o problema está no servidor, não no código.

### Opção 3: Verificar IP Bloqueado

Mod_Security pode estar bloqueando seu IP.

**Verificar:**
- Tentar de outro IP/rede
- Perguntar ao desenvolvedor se IP precisa ser liberado

### Opção 4: Ajustar Payload

Alguns caracteres podem ser interpretados como maliciosos:
- Aspas simples/duplas
- Tags HTML
- Comandos SQL
- Scripts

**Nosso payload está limpo, mas podemos:**
- Remover acentos dos nomes
- Limitar tamanho de strings
- Escapar caracteres especiais

## 🔍 POSSÍVEIS AJUSTES NO SERVIDOR

O desenvolvedor pode precisar:

### No Mod_Security:
```apache
# Desabilitar regra específica
SecRuleRemoveById [ID_DA_REGRA]

# Whitelist do User-Agent
SecRule REQUEST_HEADERS:User-Agent "NovoMundo-DisparadorEmail" "phase:1,allow,id:1000"

# Whitelist do endpoint
<LocationMatch "/dvprocessamento/">
    SecRuleEngine Off
</LocationMatch>
```

### No .htaccess:
```apache
# Desabilitar Mod_Security para este endpoint
<IfModule mod_security.c>
    SecRuleEngine Off
</IfModule>
```

### Liberar IP:
```apache
# Whitelist do IP
SecRule REMOTE_ADDR "@ipMatch 123.123.123.123" "phase:1,allow,id:1001"
```
